# 硬件验证记录

本文件只记录真实目标硬件上的结果。主机 GCC 测试、静态检查和文档审查不能填充“实机通过”。当前没有新的烧录或机械测试记录，因此下表按 `NOT_RUN` 或 `SKIP` 保持保守状态。

## 状态定义

- `PASS`：在目标硬件上完成可重复测试并满足验收条件。
- `FAIL`：目标硬件测试失败，必须记录现象、条件和后续修复。
- `SKIP`：测试依赖的工具、设备或条件当前不存在。
- `NOT_RUN`：尚未执行，不能视为通过。

## 测试记录模板

后续每次实机测试至少记录：

- 日期、固件提交、供电电压、驱动细分、电机电流和负载。
- 测试动作、按键操作、OpenMV 报文、预期结果和实际结果。
- 失败时的串口日志、SD 卡文件、视频或示波器波形。
- 是否可以重复三次以上，以及是否存在失步、抖动、过冲、异常开启或上电误动作。

没有这些证据时保持 `NOT_RUN`，不把“代码看起来正确”写成硬件通过。
