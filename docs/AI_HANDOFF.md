# 工创赛项目迁移衔接文档

本文用于把当前对话和网页调试台迁移到另一个工程。它记录的是已经落地的网页行为、当前 ULog43 日志假设、工程文件位置和必须重新确认的事项。新工程接手后，先阅读目标工程自己的 `AGENTS.md`、项目状态、架构和决策文档，再把本文作为网页调试台的补充上下文。

## 1. 当前目标

项目面向四轮麦克纳姆轮小车的“智能搬运”赛道，网页首先服务于底盘调试：

- 导入日志后检查数据质量和采样时间；
- 从四轮编码器重建车体系 `vx`、`vy` 和角速度；
- 显示车体中心、四个轮子的独立轨迹、目标轨迹和估计轨迹；
- 在比赛场地示意底图上查看轨迹；
- 以 VOFA 风格分模块查看轨迹、波形、PID、数据质量和运动分段；
- 在轨迹页右下角使用可展开、可最小化的波形小窗；
- 回放轨迹并支持 0.25/0.5/1/2/4/8 倍速；
- 对速度、跟踪误差和停车稳定性做窗口统计。

网页只分析已经记录的数据，不虚构电机输出、视觉状态、抓取结果或比赛得分。

## 2. 网页工程文件

从当前工程迁移网页时，优先整体复制以下目录和文件：

```text
viewer/index.html       可编辑页面模板
viewer/viewer.css       页面样式
viewer/viewer.js        页面逻辑、日志解析、运动学和绘图
viewer/build.cjs        生成离线单文件页面
viewer/README.md        网页使用说明和数据依据
viewer/test.cjs         viewer 相关测试
```

构建后生成的离线页面位于工程根目录：

```text
kart_log_view_mecanum_v4.html
kart_log_view_mecanum_v3.html
```

构建命令：

```powershell
node viewer/build.cjs
```

生成的 HTML 不需要服务器、网络或外部库，直接用浏览器打开即可。修改网页时编辑 `viewer/` 源码，不能只修改生成的 HTML，否则下次构建会覆盖手工修改。

## 3. 当前网页交互

### 轨迹与场地

- 场地页默认绘制比赛场地矢量示意底图；
- 显示车体中心轨迹以及 `FL`、`FR`、`RL`、`RR` 四条轮心轨迹；
- 每个轮子都有“独看”开关，可单独查看或组合查看；
- 支持目标轨迹、估计轨迹、滚轮缩放、拖动平移、适配全部和单击轨迹定位；
- 支持场地配准：填写日志原点在场地中的 `X/Y` 和旋转角；当前默认值只是示例，不能作为现场测量值；
- 四轮轨迹不是四套独立定位结果，而是由车体位姿和轮心相对车体偏移计算得到。

### 波形与回放

- 轨迹页右下角直接显示波形小窗，无需切换浮动布局；
- 小窗可切换底盘速度、四轮速度和跟踪误差；
- 小窗与轨迹共用时间轴，支持时间缩放、拖动和单击定位；
- 点击“展开波形”进入完整波形工具，点击标题栏 `⌁` 图标后缩成圆形图标，再点击图标恢复；
- 支持波形幅度缩放和拖动调整图高；
- 回放支持暂停、从头播放、进度拖动、倍速和键盘控制；
- 统计值只针对当前时间窗口，不能解释为自动比赛评分。

## 4. 当前日志通道假设

下面的定义来自当前 STM32 工程的 ULog43 输出。新工程必须逐项核对，不能仅因为列数相同就直接复用。

| 通道 | 含义 | 单位/备注 |
|---|---|---|
| `ch5` | 时间戳 | ms；导入后首帧归零 |
| `ch14` | 目标角速度 | rad/s |
| `ch15` | 记录角速度 | rad/s；旧转换日志可能全为 0 |
| `ch16` | 底盘航向 | deg |
| `ch17` | IMU 航向 | deg |
| `ch18` | 目标角速度 | deg/s |
| `ch19` | 目标平移速度大小 | 需要乘 `0.073632`，无方向 |
| `ch20` | 四轮绝对轮速均值 | 不能当作 `vx` |
| `ch21..23` | 目标 X/Y/航向 | 位置和角度 |
| `ch24..26` | X/Y/航向误差 | 位置和角度 |
| `ch27` | 左前轮目标速度 | pulse/s；只记录这一只目标值 |
| `ch28..31` | 四轮实测速度 | 依次 `FL/FR/RL/RR`，pulse/s |
| `ch32..33` | 底盘位置 X/Y | m |
| `ch34` | 累计路程 | m |
| `ch39` | 车体系横向误差 | m |
| `ch42` | 航向误差 | deg |

机械参数和符号约定：

```text
轮半径 r = 0.04 m
每轮每转脉冲数 = 440 pulse
完整轴距 = 0.186 m
完整轮距 = 0.22 m
旋转力臂 L = (0.186 + 0.22) / 2 = 0.203 m
vx：车体向前为正
vy：车体向左为正
角速度：逆时针为正
```

先把轮速换算为轮缘线速度：

```text
p2m = 2*pi*r/440
```

令 `a/b/c/d` 分别为 `FL/FR/RL/RR` 的有符号轮缘线速度，当前网页使用：

```text
vx = ( a + b + c + d ) / 4
vy = ( -a + b + c - d ) / 4
omega = ( -a + b - c + d ) / ( 4 * L )
```

这些量是编码器运动学估计，不是对地真实速度，不能单独识别打滑。当前固件没有独立记录 `vx/vy` 目标、后三个轮子的目标速度、PWM/控制输出或累计编码器计数；网页应继续显示“未记录”，不能把缺失值替换成零。

## 5. 日志格式和数据质量

网页支持：

1. 原生 ULog43 CSV；
2. 文件头含 `# converted from ULog26 -> kart_log_view 43ch` 的转换日志；
3. 带字段名的 CSV。

导入时会报告文件行数、有效行、异常行、注释行、表头行、缺失字段、时间范围、中位采样间隔、P95/最大采样间隔、重复或倒退时间戳以及长时间缺口。重复/倒退时间戳会拒绝导入；超过中位周期 3 倍的缺口会断开轨迹和波形。

当前真实样例约为 2216 帧，采样周期约 50 ms，不能按旧页面的固定 20 ms 处理。没有时间通道时才使用配置帧周期。

## 6. 迁移步骤

1. 将 `viewer/` 目录复制到新工程，保留 `build.cjs` 和 `README.md`。
2. 将当前生成的 `kart_log_view_mecanum_v4.html` 一并复制，作为无需 Node.js 的交付页面；如需兼容旧入口，同时复制 v3。
3. 在新工程中确认日志输出模块的通道、单位、轮序、轮径、轴距、轮距和时间周期。
4. 若日志格式改变，先修改 `viewer/viewer.js` 的字段映射和数据质量逻辑，再运行构建。
5. 用新工程的真实日志验证直行、后退、左/右横移和原地旋转四种基本运动；重点检查 `vy` 和 `omega` 符号。
6. 重新填写场地配准参数，并把示例值替换为现场测量值；底图只是比赛示意，不能作为判罚或尺寸依据。
7. 运行网页主机测试，确认轨迹、波形、回放、缩放、缺失值和时间缺口行为。

建议保留本文件，放在新工程的 `docs/AI_HANDOFF.md`；若新工程已有同名文件，应合并内容而不是覆盖其工程专属约束。

## 7. 验证边界

当前网页主机测试覆盖真实日志、采样时间、前进/后退/横移/旋转、麦轮运动学、四轮独立显示、轨迹缩放和平移、波形缩放、回放倍速、缺失值、时间缺口/回绕、转换日志、字段名 CSV 和波形小窗最小化，状态为 `PASS`。

浏览器自动化无法在当前环境可靠验证本地 `file://` 页面中的真实 CSS 布局和全屏行为；Canvas 内容已做渲染检查。STM32 Keil 编译、烧录、OpenMV 通信、底盘运动、机械动作和比赛现场验收均不由网页测试替代，当前均应标为 `NOT_RUN`，除非在目标设备上完成并记录证据。

## 8. 与固件工程衔接时的硬约束

若新工程同时迁移固件，继续遵守以下约束：

- 保留 TIM6 的 1 ms 电机更新和 10 ms 底盘环；
- `Control/mecanum_chassis.c` 仍是唯一底盘执行层；
- UART 中断只接收、转发或排队，不能在回调中执行控制或阻塞发送；
- USART3 保留视觉用途，不能增加第二个 UART 回调或第二个底盘控制层；
- 不得未经明确要求修改电机方向、编码器方向、轮径、轮距、PID、引脚和定时器资源；
- 没有实机证据时，不得声称存在自动回零、限位闭环、真实打滑识别或机械验收通过。

接手新工程后的第一轮检查顺序应为：读取新工程 `AGENTS.md`、项目状态、架构和决策文档，检查 Git 分支和工作区，再核对日志生成代码与本文通道表。不要把本文中的默认机械参数直接当作新车型参数。
