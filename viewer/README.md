# 智能搬运 · 麦克纳姆调试台

## 伯德图与频域初选

PID页导入200Hz CSV，选择FL/FR/RL/RR，查看“伯德图 · 频域 PID 初选”。确认目标是
预先设定、与反馈扰动独立的测试信号，再点击计算。一般行车位置闭环产生的轮速目标不能
自动当独立参考；网页无法从CSV本身证明这一点。换文件后需重新确认。

采用不重叠Hann窗分组互谱，`G=S_yr/S_ur`，不是单次FFT的Y/U，也不把闭环Y/R当电机。
两半窗分别检查目标与输出/轮速的相干性、频率响应一致性。灰点仅供诊断，蓝点满足相干性
≥0.8、两半幅差≤3dB/相差≤20°与参考能量要求；仍有有限窗谱泄漏/闭环噪声偏差。
至少8窗、8个可靠频点、4倍频宽。频率轴用日志控制周期，5/6ms时间量化不插值。
仅单方向工作点小扰动；饱和>1%、近零速>5%、输出slew或同向钳制>5%、大幅调制时不初选。

PI相位整形种子与P/I局部搜索独立于一阶时域模型，Kd保持实际值；实际参数±20%且不越固件
范围。按离散积分/误差微分计算C(z)G，前馈不是反馈C的一部分。两半频响、增益±20%与额外
一帧延迟中均要求可观测的0dB交越、带内相位余量≥55°、峰值敏感度≤1.6、带内加权敏感度
代价至少改善2%。压力情景不是统计置信区间；最高观测频点环路幅值须<0.3，未观测频段仍未知。
不外推完整增益/相位裕度、不计算新实车分数，不证明全局稳定或实际改善。

有独立验证CSV时还要求可靠频率网格相符、频响一致，否则阻止初选。没有验证文件时只是单次
试验的局部初选。点击填入只填当前轮写入区，复用原有停车写入/读回；不自动写车或启动运动。
DeepSeek原有时域提案门控不变，频域初选在网页本地计算，无需AI/API密钥。

频域采集宜在已正常连续转动的工作点附近叠加小幅多正弦/扫频，避免跨零、停滞、饱和和slew。
应覆盖预期交越附近及其两侧，重复或独立试验核对。不能保证任意路线都提供可靠频响。
20cm/s持续40秒约8米，不适用于仅2米的单向场地；不可把该速度直接套入长时间旧流程。
架空实验只适配架空负载，不能当成落地验证。本次未改变测试运动或固件。

打开工程根目录的 `kart_log_view_mecanum_v4.html`。这是可单独复制使用的离线文件，不需要服务器、网络或外部库。v3 文件同步生成相同内容，防止旧入口继续使用错误换算。

## 使用

1. 导入本工程的 ULog43 CSV；可以使用根目录 `log0_kart.csv` 验证。
2. 顶部查看车体系 vx（向前为正）、vy（向左为正）、角速度（逆时针为正）和速度箭头。
3. 在“场地与轨迹”中用每轮旁的“独看”只显示该轮轨迹；复选框可以自由组合。滚轮缩放、拖动平移、单击任一可见轨迹定位。放大面板、全屏、适配全部可切换显示范围。
4. 波形工作台可切换底盘速度、四轮速度、跟踪误差。滚轮缩放时间、拖动平移时间，或填写起止时间；纵向拉伸改变幅度范围，右下角拖动改变图高。
5. 右侧 RMS、峰值和速度标准差只统计所选时间窗口。建议选择目标不变的稳态片段，参考值可修改；这里没有自动比赛评分或笼统稳定性评分。
6. 回放支持 0.25 / 0.5 / 1 / 2 / 4 / 8 倍速、暂停、从头播放、拖动进度、空格与左右方向键。时间来自 ch5，不按固定帧数假设。
7. 在“场地配准”填写日志原点在场地中的坐标及旋转角。默认 (2.25, 0.15, 180°) 仅是示例。场地左下为原点，X 右正、Y 上正。

## 数据依据与修正

默认通道来自 `Hardware/bsp_ulog.c`，几何和运动学来自 `Core/Src/main.c`、`Control/mecanum_chassis.c`。

| 量 | 来源 / 单位 |
|---|---|
| 时间 | ch5，ms；首帧归零 |
| 四轮实测 | ch28–31，依次 FL / FR / RL / RR，pulse/s |
| 左前轮目标 | ch27，pulse/s |
| 底盘位姿 | ch32、33（m），ch16（°） |
| 角速度目标 / 记录实测 | ch14 / 15，rad/s |
| 平移速度目标大小 | ch19 × 0.073632，m/s，无方向 |
| 横向目标偏差 / 航向误差 | ch39（m）/ ch42（°） |

默认半径 0.04 m，每轮一转 440 脉冲，完整轴距 0.186 m，完整轮距 0.22 m。换算系数 `p2m = 2πr / pulsesPerRevolution`；旋转力臂 `L = (轴距 + 轮距) / 2 = 0.203 m`。

令 a、b、c、d 为 FL、FR、RL、RR 的有符号轮缘线速度：

```
vx = ( a + b + c + d) / 4
vy = (-a + b + c - d) / 4
ω  = (-a + b - c + d) / (4L)  // rad/s
```

原页面错误地把 ch19 / ch20 当作纵向目标 / 实测；ch20 实际是四轮绝对轮速的均值，原地转动时也非零，不能代表平移速度。ch18 是角速度目标，不是实测。

旧转换样例 `log0_kart.csv` 的 ch15 全为 0，但四轮数据可还原旋转。因此默认 ω 也采用四轮运动学，参数页可切换到日志实测通道。输入日志若来自不同固件，不能仅凭 43 列自动认定语义相同，请先修改通道和单位。

## 解释边界

- vx、vy、ω 是编码器运动学估计，不直接测量相对地面的真实速度，无法独立识别打滑。
- 四轮轨迹是 `车体位置 + R(航向) × 轮心相对车体偏移`，并非四套独立二维定位结果。
- 当前日志不包含独立 vx / vy 目标、其余三轮目标、控制输出、累计编码器计数。页面明确标为未记录，可通过高级映射接入之后增加的通道。
- 横向偏差是目标位置误差投影到车体 Y 轴，并非到规划路线的最短距离。
- 底图按比赛示意重绘，仅保留 2400 mm 边界、450 mm 障碍、400 mm 中间通道、启停区和作业区；作业点位置为示意，不能替代现场测量或判罚依据。
- 时间戳重复/倒退会拒绝导入，防止跨开机日志被错误拼接；32 位毫秒计数回绕有单独处理。超过中位周期 3 倍的缺口断线显示。时间通道手动留空时才使用配置帧周期。
- 普通ULog PID分解仍是理想分解；独立PID CSV模块有条件建模预测和人工停车在线写参。预测不代表实测，模型/重放未通过时不提供自动候选。

## 第一阶段底盘调试版新增功能

- 导入时识别原生 ULog43、`# converted from ULog26` 转换日志和带字段名日志；页面显示数据来源。转换补零字段继续显示为未记录。
- “数据质量”页报告文件行数、有效行、异常行、注释、表头、缺失值、时间范围、中位数/P95/最大采样间隔和长缺口。异常行保留原始行号；缺口处轨迹、波形和积分断开。
- “运动分段”按固件阶段生成等待、平移、转弯和完成后静止段。点击一段会同步切换时间窗口、地图游标和指标；没有更细动作字段时标记来源。
- 轨迹同时显示控制目标点（虚线）和估计位姿（实线）。目标轨迹不等同于原始规划路径。
- 四轮目标/实测映射为 FL `27/28`、FR `35/29`、RL `36/30`、RR `37/31`；电机卡的轮缘线速度由实测 pulse/s 按当前轮径和每转脉冲数换算。
- 车体速度波形同时显示目标和实测。位置模式下固件 ch12/ch13 是世界坐标目标，网页按当前底盘航向换算为车体系后再与 ch10/ch11 对比；速度模式按车体系目标处理。
- ch32/ch33 是轮速与 IMU 融合的里程计估计，ch34 是该估计轨迹的采样差分累计长度；没有外部视觉或激光真值时，网页不能把它们标成绝对真实地面位置。
- 停车响应按低速阈值推断进入停止和持续稳定时间，停车位移、路径与朝向指标明确标为估计。
- “测试信息”可填写固件、测试编号、动作、地面/负载、电池和备注，并保存/恢复本机分析配置。人工填写字段不会伪装成固件记录。
- 带字段名 CSV 会按时间、位置、航向和四轮反馈别名建立映射；导入后仍可在高级映射中确认。

第二阶段再接入视觉、机构和比赛任务日志。当前工程不生成没有记录依据的视觉状态、抓取结果或比赛得分。

## 轨迹页波形小窗

进入“场地与轨迹”后，右下角直接显示波形小窗，无需切换浮动布局。可以选择底盘速度、四轮速度或跟踪误差；播放和定位沿用同一条时间轴。

点击“展开波形”查看完整时间/幅度工具，点击“收起波形”或按 Esc 回到小窗。切换到其他页签后波形恢复普通卡片，返回轨迹页时自动显示小窗。小窗内仍支持滚轮缩放时间、拖动时间和单击定位。

### 波形小窗最小化

轨迹页右下角的波形小窗标题栏有一个 `⌁` 图标按钮。点击后波形小窗缩成只含图标的圆形按钮，不遮挡轨迹；再次点击圆形图标即可恢复。切换到其他页签时，图标会随轨迹页小窗一起隐藏，返回轨迹页会恢复波形小窗。

### BT10 实时日志（可选）

在 Chrome/Edge 的安全页面中也可以点击“直接连接 BT10”，网页会通过 Web Bluetooth 连接 FFE0/FFE1，实时显示日志，并在收到 `#BTLOG,END` 后自动下载 CSV。连接后点击“发送 BT10 自测”会通过 FFE2 写入 20 行 43 列测试日志；BT10 的 UART 必须回传这些数据（串口回环或 MCU 回显），网页才能验证完整收发链路。若浏览器禁止从 `file://` 页面使用蓝牙，请在工程根目录执行 `python -m http.server 8000`，再打开 `http://127.0.0.1:8000/kart_log_view_mecanum_v4.html`。

也可以点击“串口自动回显”，选择 BT10 对应的 COM 口。网页会以 115200 8N1 打开串口，把从 BT10 UART 收到的每个数据块原样写回，不再需要串口助手手动复制粘贴。此时网页应同时保持 BLE 连接；不要让 Python 接收器或其他串口工具占用同一个 COM 口。

“一键自测”会按顺序完成 BLE 设备选择、串口选择、115200 8N1 自动回显和 43 列测试日志发送。不同电脑不需要预设 COM 号；首次使用时在浏览器弹窗中分别选择 BT10 和对应的 USB 串口。功能需要 Chrome/Edge，并且网页必须来自 `http://localhost`、`http://127.0.0.1` 或 HTTPS；`file://` 页面可能被浏览器禁止访问蓝牙或串口。

Windows 采集器可以把 BT10 收到的换行数据通过本机 WebSocket 转发给页面。打开页面后，在顶部输入采集器地址（默认 `ws://127.0.0.1:8765`），点击“连接实时日志”。采集器应原样转发 `#BTLOG,...` 状态行和 43 列 CSV 行；页面会忽略状态行，按当前 ULog43 通道定义追加数据并实时更新 vx、vy、位姿、轨迹和波形。收到 `#BTLOG,END,...` 后页面保留已接收数据并显示结束状态。

WebSocket 只负责本机显示，完整 CSV 仍由 Windows 采集器写盘。网页断开或关闭不会从 BT10 补回历史数据；正式比赛应以采集器保存的 CSV 为准。
