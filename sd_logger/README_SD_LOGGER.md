# USART2 日志停录与 TF 卡收尾

2026-11-05 更新。STM32 通过 PD5 / USART2_TX，以 115200、8N1 向外接串口转 TF 记录仪发送 43 列 CSV；文件创建、缓存写入和关闭由外接记录仪负责，本工程没有直接操作 TF 的 FatFs 文件句柄。

## 本次修复

- 比赛模式在 `AppRace_Init()` 前调用 `ULog_Init()`，每次 `AppRace_Poll()` 后调用 `ULog_Poll()`。此前比赛模式跳过了这两个调用。
- 正常记录间隔 50 ms，上电等待 2000 ms 后才开始发送。此等待不是记录仪就绪确认。
- 检测到流程结束时，不再等待下一个 50 ms 周期，尝试发送一条最终状态，然后锁定停录。若结束发生在上电等待期间，则直接停录，不向尚未就绪的记录仪补发。
- `ULog_Poll()`、`ULog_WriteRaw()` 和 `ULog_Printf()` 均受停录开关控制；重复调用 `ULog_Init()` 不会重新开始。重新记录须复位主控。
- UART 发送失败时计数并停录，避免在可能的半行后继续追加。非有限数值（NaN/Inf）也计数并停录；最终行格式化失败或底盘指针无效时仍会停录，不会反复尝试最终行。
- 旧正方形流程的完成、超时、运行后主动中止均会停录。

## 发送给 kart_log_view_v4 的新增字段

仍保持 43 列，不改变网站导入格式。网站默认使用以下新增通道：

- ch2/ch3/ch6/ch7/ch9：比赛状态、路线动作索引、错误码、任务队列索引、任务队列完成标志。
- ch10/ch11：实测车体系 `vx/vy`，单位 m/s；网站不再只依赖四轮反算。
- ch12/ch13：目标车体系 `vx/vy`，单位 m/s；网站波形可以直接比较目标和实测。
- ch27/ch35/ch36/ch37：FL/FR/RL/RR 目标速度，单位 pulse/s；ch38 是四轮最大绝对控制输出。
- ch40/ch41：驱动器 VIN、主控 VIN，单位 V。比赛模式现在也初始化并轮询电池 ADC。

此前 ch35/ch36 是实测轮速副本，现已改为补齐四轮目标速度；实测轮速仍由 ch28–ch31 提供。ch38 记录四轮最大绝对控制输出，但没有每个轮子的独立输出。累计编码器计数暂未占用 43 列，后续若需要应替换重复字段并同步网站映射。ch41 不再重复目标角速度，目标角速度使用 ch14，实测角速度使用 ch15。`kart_log_view_mecanum_v4.html` 的默认映射和原始通道标签已同步更新。

## 当前程序中“流程结束”的含义

当前配置为 `APP_MODE_RACE`，且 `RACE_PICK_ENABLE=1`、`RACE_PICK_DIRECT_KEY_TEST=1`，实际执行的是独立夹取测试。上电复位不算完成；第一次夹取结束、自动复位结束且舵机/步进不再忙，才停录。后续再次按键不会自动重启日志。故障或中止也会停录。

关闭独立夹取测试后，现有比赛执行器只接通了到原料区及可选的首件夹取。`RACE_DONE` 表示到原料区路线结束，日志会继续覆盖尚在执行的夹取，待当前已实现的动作全部停止后停录。**这不表示整场比赛任务队列已经执行完毕。** 后续导航、粗加工、暂存和返回流程尚未接通；接通后必须把 `AppRace_LogFinished()` 的正常结束条件改为最终任务队列完成（`RaceTaskPlan_Done(&s_plan)`）并确认执行机构空闲，不能继续把原料区的 `RACE_DONE` 当整场终点。

比赛模式 CSV 保持 43 列：ch2 为 RaceState，ch3 为路线动作索引，ch6 为 RaceError，ch7 为任务队列索引，ch9 为整个任务队列是否完成。ch1/ch8 的 4 表示本次日志流程结束，不等于整场任务成功；夹取测试结束时 RaceState 仍可能为 READY。旧查看器的 sq_st/sq_step 标签在比赛模式下应按上述含义阅读。

## 停止发送与安全断电

`ULog_IsRecording()==0` 仅表示主控日志流已停，不表示 TF 文件已同步或关闭。成功的阻塞发送等待 UART 的 TC 标志后返回，但接收端仍可能缓存数据或保持文件打开。

工程保存的 `param_config.txt` 中有 `#cmden:0` 和 `#timeout:100`。尚无该记录仪型号和协议文档，不能断言 timeout 的单位或它是否执行文件关闭，也不能据此宣称等待 100 ms 即可断电。本次未修改记录仪配置、未发送猜测的退出/关文件指令。

要确认可安全断电，需要按记录仪手册执行 flush/close 指令并确认应答，或者确认其空闲自动保存/关闭机制及规定的等待条件。在确认前，不要把“主控停录”当作可以立即断电或拔卡的信号。

实车验收：检查最终行之后 PD5 是否保持无新数据；继续等待至少数分钟，确认文件大小不再因主控日志增加；按记录仪手册确认保存/关文件完成，再断电读卡，检查最后一行和文件系统。发送失败时最后一行可能残缺，应结合 `g_ulog_tx_error_count` 判断。
