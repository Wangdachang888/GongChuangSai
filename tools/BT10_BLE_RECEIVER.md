# BT10 Windows BLE 日志接收器

`bt10_ble_receiver.py` 使用 Windows BLE GATT 接收 STM32 USART2 的文本日志，
并原样保存为 CSV，现有 `viewer/kart_log_view_mecanum_v4.html` 可直接导入。

## 使用

```powershell
python -m pip install bleak websockets
python tools/bt10_ble_receiver.py BT10 -o bt10_logs\run01.csv --no-console --websocket
```

若固件同时发送独立 PID Burst（以 `#BTLOG,PID_BEGIN` 开始、`#BTLOG,PID,`
逐行发送、`#BTLOG,PID_END` 结束），可加 `--pid-burst`：

```powershell
python tools/bt10_ble_receiver.py BT10 -o bt10_logs\run01.csv --pid-burst --no-console --websocket
```

它会把 PID Burst 保存为同目录的 `run01.pid.csv`，主日志仍原样保存为
ULog43 CSV。`PID_BEGIN` 后的字段名应使用网页支持的带字段名格式，例如
`timestamp_ms,fl_target,fl_actual,fl_output,...`；也接受 `#BTLOG,PID,{...}`
JSON 行并按首个对象的键生成表头。PID 文件在 `PID_END` 或蓝牙断开时执行
flush/fsync/close；不启用 `--pid-burst` 时这些行仍会原样保存在主日志中。

`BT10` 可以替换为 Windows 蓝牙设置中显示的设备名或地址。程序使用 WHEELTEC
BT10 的 FFE0 服务、FFE1 通知特征和 FFE2 写入特征。收到
`#BTLOG,END`（也兼容带附加字段的 `#BTLOG,END,...`）后执行 flush、fsync 并关闭文件；蓝牙断开时也会保存已收到的
最后一段数据。

不带 `--no-console` 时，可以在控制台输入 `@GET,STATE`、`@GET,PARAMS` 和
`@SET,...` 等命令。接收到 `#BTLOG,STATE,RUNNING` 后，主机不会发送 `@SET`，
但仍允许查询状态和参数。最终权限检查仍必须由 STM32 执行。

`--websocket` 为网页实时曲线开启本机转发，默认监听
`ws://127.0.0.1:8765`。网页连接或关闭不会影响 CSV 保存；省略该选项时无需
安装 `websockets`，接收器仍可单独保存日志。


## 持续实时 PID 与最近 20 秒缓存（2026-11-21）

1. 重新编译并由使用者烧录固件；将 BT10 串口端设置为 **230400、8N1**。
   MCU USART2 同步为 230400；普通 ULog43 保持 20 Hz。旧 TF 记录器若接在
   同一串口，也需匹配波特率，但不应把二进制 PID 帧当作旧 CSV 文件。
2. 用 Chrome/Edge 打开根目录 kart_log_view_mecanum_v4.html，直接连接 BT10。
   需要双向接线：PD5→模块 RX，PD6←模块 TX，共地。
3. PID 页面先点击“网页协议自测（模拟）”，确认四轮曲线、2000 帧数据和分析；
   模拟自测需断开实车/电脑日志源，不能代替实物蓝牙验收。
4. 连接实车，开机至少等待 2 秒，停车时点击“开始持续实时采集”。
   收到 PID_ARMED 才表示实际启动。此命令不驱动车辆、不改 PID；
   按原来的流程运行小车，计时从开始命令成功即刻开始，包含等待运动时间。
5. 200 Hz 实时流持续到手动停止或整车日志终止；100 Hz 缓存满 2000 帧后循环覆盖，
   不会停止实时流。点击“停止采集 / 冻结最近 20 秒”后冻结当前缓存。
   **停止采集不会让车停车。** 按原流程停车且退出 RUNNING 状态，
   命令目标接近零、四轮实测小于 10 pulse/s 持续 500 ms 后分批上传。
6. 页面显示实收/应收帧数、实时序号缺口、CRC 错误、量化裁剪数；上传结束后
   自动进入现有 PID 指标/候选分析，可下载独立 CSV。日志仓库条目另有
   “缓存 PID 分析”入口。另用“下载完整实时 PID CSV”导出本会话全部实收
   200 Hz 数据；“下载停车缓存 CSV（100 Hz）”仅导出最后 20 秒。两者均可导入
   PID 分析页，不混作普通 ULog43。电脑接收器加 --pid-burst 也能保存独立停车缓存文件，
   同一接收会话的后续 Burst 使用 _2、_3 后缀，避免覆盖上次记录。

运行时默认不采集；命令仅为 @PID START\n、@PID STOP\n。
无需安装 Python 即可用网页直连。Python 接收器可继续做接收、保存和 WebSocket 转发，
但网页开始/停止按钮只向直接连接的 BT10 发送命令。整车日志 END 仍会锁定停止，
下一轮整车采集需要按现有方式复位；不要在上传完成之前断电。

### 数据与实时边界

- TIM6 电机调用 1 ms、底盘环 10 ms 均保持不变；现有 Motor 内部测速/PID
  窗口实际是 5 ms（200 Hz），并非每 1 ms 都重新计算速度 PID。
- 实时上传目标 200 Hz，每帧 36 字节，约 7.2 KB/s；界面绘图限制为约 10 Hz，
  数据接收频率与显示器刷新率不同。主循环或 BLE 拥塞会降低实收率，缺口可见。
- RAM 以环形缓存独立保存最近 100 Hz×2000 帧，首末时间跨度 19.99 秒，内存 56,000 字节。
  未满 20 秒时保留全部已采样记录；满后覆盖最早数据，停止后按时间顺序上传。
  PID_STATS.overwritten 统计正常覆盖量，不表示无线丢包；live_drop 单独表示发送侧实时丢帧。
  每帧时间戳为 u32，12 个通道为有符号 i16，分辨率 0.1，
  范围 -3276.8～3276.7 pulse/s / 控制输出单位；超界和非有限值会统计裁剪，
  不能把裁剪后的曲线当作原始真实值。输出是前馈+PID+kick+限幅后的总输出，
  不是实测电压或电流。
- 中断内固定次数取值、量化和复制，不格式化、不发串口、不分配内存；
  主循环每轮最多发一帧，每帧 CRC16 校验。队列紧张优先丢实时帧，
  保留整车日志空间，停车记录上传则暂停重试同一索引。
- USART2 日志 IRQ 降为优先级 5，避免抢占优先级 4 的 TIM6；USART3 与电机参数未改。
- 内存不是掉电存储；没有 BLE 应用层 ACK/自动补传承诺，链路断开仍可能丢失电脑端数据。
  有效日志需核对 PID_STATS 的 count 与实收帧数。BT10 吞吐、TIM6 最坏耗时和
  实车同时运行视觉/机构时的表现均为 NOT_RUN。

### 二进制协议 v1

固定 36 字节，小端：A5 5A 01 kind seq:u16 timestamp_ms:u32 values:12*i16 crc:u16。
kind=1 实时、kind=2 停车记录；CRC 为 CCITT-FALSE（初值 FFFF，多项式 1021），
覆盖第 2～33 字节。12 个值按 FL、FR、RL、RR，每轮 target/actual/output。
实时 seq 从 1 开始，记录 seq 从 0 开始。普通 ASCII 行与二进制帧交错发送；
接收端需先按字节组包，再解码 ASCII，不能对整条链路直接做 TextDecoder。

Python 将实时帧转换成 #BTLOG,PID_LIVE,seq,...，停车帧转换成 #BTLOG,PID,...，
这样旧 ULog43 和现有 PID CSV 分析继续兼容。
BEGIN/END 与 PID_STATS 仍为 ASCII。原始文本 PID Burst 接收也继续保留。

### 电脑端持续保存与容量

- 网页仓库使用 IndexedDB v2；保留旧版整段文本记录，新会话按约 1 秒或 64 KiB
  文本分段写入，不反复复制整个会话，也不保留一份无限增长的 bt10.raw。
  分段写入及元数据在同一事务提交，失败时保留待写文本并显示错误，重试不重复写入。
- 实时 PID 图表保留最近 4000 帧，累计帧数另行显示；图表窗口不是保存上限。
  完整实时 PID 下载从全部仓库分段提取 PID_LIVE，停车缓存下载仍只含 PID 数据帧。
  仓库“下载会话”保留整车、实时 PID、停车缓存与元数据，便于追溯。
- 230400 8N1 的串口理论有效载荷上限为 23,040 B/s；实时 PID 二进制约 7,200 B/s，
  另有 20 Hz 整车 CSV 和状态信息。串口预算不能证明 BLE 实际吞吐；仍需核对缺口和
  实收帧数。本次不改变频率、串口配置、队列优先级和控制代码。
- 浏览器保存的是展开后的文本，大小随数值位数变化，通常比无线二进制大。
  持续记录没有固定 20 秒限制，但受浏览器配额、电脑资源和连接时长限制；并非无限保存。
  配额不足时按页面错误处理、导出并清理旧记录。换浏览器/电脑不会自动迁移仓库。
- 请保持网页和蓝牙连接，结束后等待缓存上传完成并下载备份。刷新/关闭/崩溃可能丢失
  尚未提交的最后一段；页面隐藏时会尝试刷新待写数据，不能保证关闭瞬间异步写入完成。
  断链期间实时数据不能由最后 20 秒缓存恢复成完整 200 Hz 历史。
- 网页协议自测现在模拟 30 秒 / 6000 帧实时数据和最后 20 秒 / 2000 帧缓存；
  此自测仅验证解析、显示和缓存时序。分段保存、重试及更长会话由主机回归测试验证，
  真正的 BT10 连续吞吐、浏览器 GATT 和实车时序仍为 NOT_RUN。


## 在线读取和写入实际 PID（2026-11-21）

本节需要对应新版固件；旧固件只有 START/STOP，会在参数读取时超时。
第一次由使用者编译并烧录一次；后续改 RAM 参数不需要再次编译/烧录。

1. Chrome/Edge 打开更新的 v4 网页，直接连接 BT10。网页自动读取七组 PID；也可在
   PID 页点击“读取车辆全部 PID”。必须看到车辆回传的值，不能把网页离线输入当成实车值。
2. 可分别选择 FL/FR/RL/RR 速度环、X/Y/TH 位置环。页面显示 Kp/Ki/Kd、计算周期、
   积分/输出限幅和参数版本；选中通道还显示前馈、死区、斜坡、低通及 kick 等只读配置。
   默认速度环为2.5/1.6/0，X/Y为1.6/0.05/0.12，TH为3.2/0.08/0.18；在线表以实车为准。
3. 停车时开始持续PID采集，再按原流程运行。每次 START 会附带七组 PID_USED 快照，
   独立实时CSV、停车CSV和仓库会话均保留这些快照；Python --pid-burst 的独立文件也保留。
   采集中/待上传时禁止SET，因此本轮速度环样本不会跨在线写入混用参数。
4. 停止采集并按原流程停车，等待缓存上传。选择目标轮子，候选分析使用这轮日志里
   该轮的实际 PID 基准和单轮指标；“填入”只把候选填到编辑区。
   缺失/混合参数快照、运动样本不足时不能直接填入。手动编辑仍可用。
   这套候选来自速度环数据，不能套到位置环；位置环本次支持手动在线读写。
5. 点击“停车写入并读回确认”。网页先 GET 当前版本，再 SET 所选通道，再 GET 核对。
   只有读回值和版本一致才显示成功；其他通道、前馈和限幅不变。
   固件要求 READY 或已完成的 DONE、速度模式、四轮零目标/零输出、实际轮速绝对值
   <10 pulse/s 持续500ms，且没有采集/待补传；运行、故障、取消、旧版本、非法数值都会拒绝。
   该门控不使用故障补传的“输出归零”兜底，不能用冻结反馈冒充安全写入。
6. 写入后可载入上一组参数再写回；已确认参数自动保存在当前浏览器本机存储。
   RAM 参数复位后恢复源码默认值。比赛不接受远程重启，仍按原方式复位/启动；下一轮应先
   读取车辆，再点“载入本机保存值”，然后写入并确认，最后开始采集并按原流程启动。
   不支持浏览器替车辆自动跑圈，也不自动写Flash。切换电脑/浏览器来源不会自动同步本机值。

整车 END 后仍处理显式 PID 参数请求，但不重启整车日志或比赛；参数应答不另开仓库会话。
断线/超时后写入结果可能未知；网页不自动重发 SET，必须重新读取确认。GATT文本命令按
20字节分片串行发送，接收中断仍只排队，主循环每轮最多解析32字节/一条命令。

### 参数协议

- `@PID GET <id> <axis>\n`
- `@PID SET <id> <expected_revision> <axis> <kp> <ki> <kd>\n`
- axis：FL、FR、RL、RR、X、Y、TH；id为非零u32；revision为本次上电参数修改版本。
- 回复：`#BTLOG,PID_PARAM,id,revision,axis,READ或SET,kp,ki,kd,integral_max,output_max,period_ms,ff_gain,deadzone,ff_min_speed,ramp,slew,lpf,kick_step,kick_max,stuck_ratio,editable`
- 失败：`#BTLOG,PID_ERROR,id,reason`；版本不符返回STALE_REVISION，不执行写入。
- 采集快照：同参数回复字段，以 `#BTLOG,PID_USED,0,...` 开头，供离线分析；版本只统计
  在线SET，数值直接读取实际控制对象。非比赛Square模式临时修改航向PID的逻辑不被改写，
  START快照不能声称覆盖这种模式全部运行期间的自动增益变化，需要时另行查询实际值。
- 速度环范围：Kp 0～10、Ki 0～8、Kd 0～3；位置环：Kp 0～20、Ki 0～5、Kd 0～3。
  保留原PID计算、前馈、总输出限幅、TIM6 1ms/10ms和USART2 230400资源。

AI复核只接收所选轮子指标、日志中的实际参数和候选排序；缺快照会标为未验证离线基准。
AI不调用蓝牙、不执行写入。主机模拟与编译已验证；真实GATT读写、停车效果、参数效果、
TIM6最坏耗时和重启后人工重应用仍为NOT_RUN，不能据此声称实车调参已验收。
